# NUTRI_FIT

> AI 기반 개인 맞춤형 영양제 분석 및 복용 관리 웹 서비스

## 📌 프로젝트 소개

**NUTRI_FIT**은 영양제 사진을 업로드하면 OCR과 AI를 활용하여 제품 정보를
분석하고, 사용자의 생활 패턴을 기반으로 영양제의 복용 정보를 제공하는 웹
서비스입니다.

사용자가 영양제를 보다 편리하게 관리할 수 있도록 **영양제 등록 → AI 분석
→ 복용 일정 관리 → 복용 알림**의 흐름으로 서비스를 구현했습니다.

------------------------------------------------------------------------

## 🎯 프로젝트 목적

일반 의약품과 달리 영양제는 제품의 효과, 주의사항, 복용 시간 등의 정보를
사용자가 직접 찾아봐야 하는 경우가 많습니다.

NUTRI_FIT은 이러한 불편함을 줄이기 위해 영양제 사진을 AI로 분석하고,
사용자가 등록한 생활 패턴과 연계하여 복용 일정을 관리할 수 있도록 하는
것을 목표로 개발했습니다.

## ✨ 주요 기능

### 1. 📷 영양제 이미지 OCR

영양제 사진을 업로드하면 Python 기반 AI 서버에서 이미지의 정보를
분석합니다.

-   제품명
-   제조사
-   1일 섭취량
-   주요 성분
-   성분 함량

OCR 결과를 JSON 형태로 받아 Spring Boot에서 웹 화면에 표시합니다.

### 2. 🤖 AI 영양제 분석

OCR로 추출한 제품 및 성분 정보를 바탕으로 AI 분석을 수행합니다.

-   영양제 효과
-   추천 복용 시간
-   식사 관계
-   추천 이유
-   주의사항
-   상호작용 관련 정보

특히 사용자의 기상·식사·취침 시간 등의 생활 패턴을 AI 분석에 전달하여
**사용자 생활 패턴에 맞는 복용 시간**을 제시하도록 구성했습니다.

### 3. 💊 내 영양제 관리

AI 분석이 완료된 영양제를 사용자의 영양제 목록에 등록할 수 있습니다.

-   영양제 제품명
-   제조사
-   1일 섭취량
-   영양제 이미지
-   AI 분석 결과

등록된 영양제는 `user_supplements`를 통해 사용자별로 관리합니다.

### 4. ⏰ 복용 일정 관리

내 영양제에 등록된 제품을 기준으로 사용자가 직접 복용 일정을 추가할 수
있습니다.

-   복용 시간
-   식사 관계
-   복용 안내
-   활성화 여부

AI 분석 후 바로 복용 일정이 생성되지 않도록 기능을 분리하여,

**AI 분석 → 내 영양제 등록 → 복용 일정 추가**

순서로 관리하도록 구현했습니다.

### 5. 🔔 Web Push 복용 알림

브라우저 Web Push API를 활용하여 휴대폰으로 복용 알림을 전송합니다.

-   브라우저 Push 구독
-   Push 구독 정보 DB 저장
-   VAPID 기반 Push 인증
-   테스트 Push 전송
-   복용 시간 기반 자동 알림

Spring Scheduler가 `intake_schedules`를 주기적으로 확인하여 설정된 복용
시간이 되면 Push 알림을 전송합니다.

### 6. 📝 복용 기록 관리

복용 일정과 연결된 복용 기록을 관리할 수 있도록 `intake_logs` 테이블을
구성했습니다.

복용 상태를 다음과 같이 관리할 수 있도록 설계했습니다.

-   `PENDING`
-   `TAKEN`
-   `MISSED`
-   `SKIPPED`

## 🗄️ 데이터베이스 구조

주요 테이블은 다음과 같이 구성했습니다.

  테이블                     설명
  -------------------------- ------------------------------------------
  `users`                    사용자 정보 및 생활 패턴, Push 구독 정보
  `supplements`              영양제 제품 정보
  `ingredients`              영양제 성분 정보
  `supplement_ingredients`   영양제와 성분의 관계
  `user_supplements`         사용자별 등록 영양제
  `intake_schedules`         영양제별 복용 일정
  `intake_logs`              실제 복용 기록

### 주요 관계

``` text
users
  │
  └── 1:N ── user_supplements
                  │
                  ├── N:1 ── supplements
                  │
                  └── 1:N ── intake_schedules
                                  │
                                  └── 1:N ── intake_logs

supplements
  │
  └── 1:N ── supplement_ingredients
                  │
                  └── N:1 ── ingredients
```

### Push 알림 관련 주요 컬럼

`users` 테이블에 Web Push 구독 정보를 저장합니다.

``` text
push_endpoint
push_p256dh
push_auth
```

이를 통해 사용자의 브라우저 Push 구독 정보를 저장하고 서버에서 알림을
전송합니다.

## 🔧 주요 트러블슈팅

### 1. Spring Boot 서버 포트 충돌

**문제**

Spring Boot 실행 시 기본 포트인 `8080`을 사용할 수 없는 문제가
발생했습니다.

**원인**

다른 프로세스에서 `8080` 포트를 사용하고 있었습니다.

**해결**

`application.properties`에서 Spring Boot 실행 포트를 `8081`로
변경했습니다.

``` properties
server.port=8081
```

------------------------------------------------------------------------

### 2. Web Push VAPID 인증 오류

**문제**

Web Push 구현 후 Push 전송 과정에서 `HTTP 403` 오류가 발생하여
휴대폰으로 알림이 전달되지 않았습니다.

**원인**

Web Push는 VAPID를 이용하여 서버를 인증하기 때문에 브라우저의 VAPID 공개
키와 서버의 VAPID 설정이 올바른 키 쌍으로 구성되어야 합니다.

**해결**

브라우저에서 사용하는 VAPID 공개 키와 Spring 서버의 VAPID 설정을
확인하고 올바른 키 정보로 맞춘 뒤 Push 전송을 다시 테스트했습니다.

이후 Push 서버의 응답 상태가 `HTTP 201`로 확인되었고 실제 휴대폰에서
알림을 수신하는 것을 확인했습니다.

> ⚠️ 실제 GitHub 저장소에는 VAPID 개인 키, DB 비밀번호, API Key 등의
> 민감한 정보를 절대 업로드하지 않습니다.

------------------------------------------------------------------------

### 3. AI 분석 후 복용 일정이 자동 등록되는 문제

**문제**

AI 분석 결과를 `내 영양제`에 등록했을 때 복용 일정까지 자동으로 생성되어
`복용 관리`에 바로 표시되는 문제가 발생했습니다.

**원인**

`/ai/register`에서 `user_supplements`를 저장한 뒤 `intake_schedules`까지
함께 저장하고 있었습니다.

**해결**

기능의 책임을 분리했습니다.

``` text
AI 분석
 ↓
내 영양제 등록
 ↓
user_supplements 저장
```

복용 일정은 사용자가 `복용 일정 추가`를 실행했을 때만
`intake_schedules`에 저장하도록 변경했습니다.
